# Stage 2 evidence — adversarial fixtures

Status: local security implementation verified. The later [stage 3 evidence](2026-11-20-stage-3-publication.md) records the public Windows/Ubuntu CI results and wire-level DNS fixtures.

The public CLI has no private-address policy override. The injection seam for loopback and a test certificate root is `internal` and visible only to the test assembly. The production path constructs `PublicAddressPolicy`. Public target addresses are validated as an entire DNS answer set before each connection; the socket takes a concrete validated IP, never a hostname.

Deterministic tests include:

- mixed public/private DNS answers: blocked with zero connections;
- DNS changing from public to private between checks: blocked with zero connections;
- a real loopback TCP listener: connection goes to the validated address without a hidden re-resolution;
- mapped IPv6 and selected special-purpose ranges: rejected;
- local TLS server with test-only trust: valid name and chain pass, wrong name, expiry and untrusted chain fail;
- local HTTPS server: a redirect to loopback is recorded but never followed; 16 KiB header budget stops oversized responses;
- user cancellation and total-budget exhaustion: never reported as success;
- incomplete or internally inconsistent reports: rejected;
- 20 synthetic DNS names/addresses: absent from JSON, HTML and Markdown artifacts.
- build-supplied Git commit SHA: embedded in a generated report and validated; local builds state `unknown`.

`dotnet test --no-restore --configuration Release` passed **37/37** tests on Windows. An independent staged-file checkout in Ubuntu (WSL, .NET SDK 10.0.300) passed locked restore, Release build with 0 warnings/errors and **37/37** tests. Its public sample endpoint run completed with **4/4** passes and exit 0. This is a real Linux userspace test, though it is not a packaged Linux release or a clean Linux machine.

The [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry) and [IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry) special-purpose address registries were consulted for reserved prefixes. Tests do not establish every possible DNS platform behavior, network path or certificate revocation condition. Public CI results are recorded in the later stage 3 evidence.

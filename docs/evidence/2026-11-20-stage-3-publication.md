# Stage 3 publication and CI evidence — 2026-11-20

The independent public development repository is [Trauma990/jitteroff-scout-core](https://github.com/Trauma990/jitteroff-scout-core), owned by the authenticated GitHub user `Trauma990`. The first source commit is [`4b8d80e`](https://github.com/Trauma990/jitteroff-scout-core/commit/4b8d80e981362e37178f456f0355cffd87af28a9). The repository was created public and without GitHub-generated starter files; the audited local `main` branch was pushed. The public repository URL returned HTTP 200 after push.

The first [CI run](https://github.com/Trauma990/jitteroff-scout-core/actions/runs/44779165477) completed successfully. Its [Ubuntu job](https://github.com/Trauma990/jitteroff-scout-core/actions/runs/44779165477/job/136436922868) and [Windows job](https://github.com/Trauma990/jitteroff-scout-core/actions/runs/44779165477/job/136436923590) each completed with conclusion `success`. CI uses locked restore, Release build and tests, with `contents: read` and pinned action revisions. Local pre-push Release build had zero warnings/errors and 37 of 37 xUnit tests passed. The final staged source had 48 files, no binary/report/key artifact paths, no matches for the known private-infrastructure pattern set, and no whitespace errors.

The [`7cd85fe` security-fixture commit](https://github.com/Trauma990/jitteroff-scout-core/commit/7cd85fe) added a local UDP DNS server whose replies switch from a public address to loopback. The test executes the production address policy and socket connector, asserts that the second observation is blocked, and verifies that the loopback TCP listener receives no connection. A second wire-level test verifies that a mixed public/loopback reply causes zero connection attempts. The existing local HTTPS fixture verifies that a redirect is recorded without following it or reading a response body. A seeded 128-case network-observation test checks JSON, HTML and Markdown for raw host/address leakage; another 128-case test checks that missing or unknown observations cannot serialize as a complete run. Fresh staged-file checkouts on Windows and Ubuntu WSL passed **41/41** tests. The corresponding [GitHub CI run](https://github.com/Trauma990/jitteroff-scout-core/actions/runs/44781192938) completed with `success` on both `windows-latest` and `ubuntu-latest`.

The [`f7e776b` report-invariant commit](https://github.com/Trauma990/jitteroff-scout-core/commit/f7e776b) centralised CLI exit-code classification behind report validation. Seeded valid and invalid report cases assert that missing, unknown, blocked and incomplete observations never yield exit 0; seeded hostile profile identifiers are rejected. The [`b9f79f3` privacy-fixture commit](https://github.com/Trauma990/jitteroff-scout-core/commit/b9f79f3) exercises secret-bearing resolver and connector exceptions, verifies that their messages never appear in JSON/HTML/Markdown, and checks that HTTP response bodies are not read or included in those formats. Local Release tests passed **44/44**. Both [CI for the exit-code commit](https://github.com/Trauma990/jitteroff-scout-core/actions/runs/44782291942) and [CI for the privacy-fixture commit](https://github.com/Trauma990/jitteroff-scout-core/actions/runs/44782434523) passed on Windows and Ubuntu. Randomized cases use fixed seeds in source so failures can be reproduced. These tests establish the specified boundaries, not every conceivable data flow.

Private vulnerability reporting was enabled and verified through the GitHub repository API. The public repository has `cli`, `dotnet`, `network-diagnostics`, `open-source`, `privacy` and `ssrf-protection` topics.

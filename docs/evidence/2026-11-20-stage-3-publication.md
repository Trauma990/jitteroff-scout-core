The [`7cd85fe` security-fixture commit](https://github.com/Trauma990/jitteroff-scout-core/commit/7cd85fe) added a local UDP DNS server whose replies switch from a public address to loopback. The test executes the production address policy and socket connector, asserts that the second observation is blocked, and verifies that the loopback TCP listener receives no connection. A second wire-level test verifies that a mixed public/loopback reply causes zero connection attempts. The existing local HTTPS fixture verifies that a redirect is recorded without following it or reading a response body. A seeded 128-case network-observation test checks JSON, HTML and Markdown for raw host/address leakage; another 128-case test checks that missing or unknown observations cannot serialize as a complete run. Fresh staged-file checkouts on Windows and Ubuntu WSL passed **41/41** tests. The corresponding [GitHub CI run](https://github.com/Trauma990/jitteroff-scout-core/actions/runs/44781192938) completed with `success` on both `windows-latest` and `ubuntu-latest`.

Private vulnerability reporting was enabled and verified through the GitHub repository API. The public repository has `cli`, `dotnet`, `network-diagnostics`, `open-source`, `privacy` and `ssrf-protection` topics.

This is a development-source publication, **not** a 0.1 release tag. [Wire-level SSRF and DNS rebinding acceptance](https://github.com/Trauma990/jitteroff-scout-core/issues/1) is evidenced above. Remaining release gates are tracked as [privacy/incomplete-result fuzzing](https://github.com/Trauma990/jitteroff-scout-core/issues/2) and [clean-install, release artifacts, checksums, SBOM and final review](https://github.com/Trauma990/jitteroff-scout-core/issues/3).
